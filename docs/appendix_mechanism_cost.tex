\section{Cost of Cross-Type Eviction}
\label{app:cost}

Only one direction of cross-type eviction moves data. When KV reclaims an
expert's super-block, the pool drops the expert's mapping and the weights
are reloaded from the host when next needed. When an expert reclaims KV
space it needs a contiguous super-block, so the cached pages sitting in
that region are copied elsewhere to keep them. This appendix measures that
copy and how often it happens.

We time data movement with CUDA events on the pool's transfer stream, in
the configuration of Section~\ref{sec:evaluation} (one NVIDIA L4, expert
slot 12\,MiB, $F=96$ pages of 128\,KiB), over 500 repetitions. A KV block
is global, so relocating one page copies it in all 16 layer buffers.

The expert load is bounded by PCIe, and any expert-offloading system pays
it. One such load costs as much as $8.4$ relocations, so keeping a warm
page is cheap next to the transfer that displaces it.

In aggregate the cost stays small even though the mechanism is busy. Over
the shift from the KV-heavy to the expert-heavy phase, the pool relocated
$6{,}866$ pages, which accounts for under $0.1\%$ of that run. The
reported speedup is
end-to-end wall-clock time measured with the mechanism running, so this
cost is inside that number rather than additional to it.

These figures cover data movement, including the GPU copies. They exclude
the host-side cost of selecting a victim, which does not grow as the pool
fills.
